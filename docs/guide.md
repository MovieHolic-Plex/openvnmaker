# VN Maker 사용 설명서

> 이 문서는 예전 README 의 상세 내용입니다. 개요와 화면은 [README](../README.md) 를 보세요.

직접 집필한 장편 비주얼 노벨과 로컬 편집기입니다. 기본 작품은 **〈비가 남긴 빈칸〉** 하나입니다. 원고와 이미지가 프로젝트에 포함되어 있으며 플레이·편집에 계정 연결이나 내부 AI 호출이 필요하지 않습니다.

**범용 제작·네이티브 배포 기능은 개발 중입니다.** 빈 작품과 여러 프로젝트, 사용자 캐릭터·표정, 원화 파일 가져오기, 게임 ZIP의 새 브라우저 복원을 지원합니다. Windows 로컬 편집기에서는 SDK 설정 후 **실행 게임** 버튼으로 Ren’Py 변환·검사·배포 ZIP 빌드를 할 수 있습니다. 아직 배포 프리뷰이며 Steam 출시 준비가 끝났다는 의미는 아닙니다. [구현 상태·검증 증거·남은 출시 요건](docs/production/status.md)을 확인하세요.

원본 애플리케이션·도구 소스에는 [MIT 라이선스](LICENSE)를 적용합니다. 의존성과 SDK는 각자의 라이선스를 유지하며, 게임 ZIP에는 플레이어에 포함되는 코드의 고지를 동봉합니다. 이 소프트웨어 라이선스가 이미지·음악 등 미디어의 이용 조건을 일괄 변경하는 것은 아닙니다. 샘플 미디어의 출처·이용 조건 정리는 출시 준비 항목으로 남아 있습니다.

## 작품과 분량

- 20개 장면, 829개 대사·서술 행, 전체 분기·조건부 본문 공백 제외 40,781자
- 3개 선택 장면, 8개 경로, 2개 엔딩. 한 경로에서 17개 장면을 거칩니다.
- 조건을 적용해 실제 읽는 경로별 본문은 34,052–34,265자: **320자/분 기준 약 106.4–107.1분**입니다. 모든 경로가 최소 90분 분량을 충족합니다. 실제 플레이 시간은 읽기 속도와 스킵·대기 시간에 따라 달라집니다.
- 앞선 두 선택을 기억하는 조건부 대사 20행 중 한 경로에서 8행이 나타납니다. 선택한 인물과 함께한 작업이 합류 장면과 엔딩에 이어집니다.
- 직접 생성한 원화 35개: 배경 12장, 이벤트 CG 8장, 배우 표정 12장, 작업 자세 3장
- 대사별 표정·배우 배치·작업 자세·카메라·배경·CG 전환을 지정합니다. 음악 전환·정지 15개와 효과음 큐 26개를 본문의 행동에 연결했습니다.
- 로컬 BGM 5곡과 효과음 10종 포함. 작품에서는 이 중 실제 장면에 맞는 소리를 사용합니다.

작품 원본은 [`packages/content/data/rain-blank.json`](packages/content/data/rain-blank.json), 원화는 `packages/app/public/assets/art/`에 있습니다. [원고·경로·연출 감사](docs/qa/studio-completion-2026-09-06/narrative.md)에서 실제 분량과 선택의 차이를 확인할 수 있습니다. 전체 저장 원고 40,781자를 한 경로의 재생 시간으로 계산하지 않습니다.

## 실행

Node **24.20.0**과 pnpm **11.24.0**을 사용합니다. Node 버전은 `.node-version`, 패키지 매니저 버전은 `package.json`에 기록되어 있습니다. [기여·검증 안내](CONTRIBUTING.md)에 환경 설정과 SDK 없는 브라우저 검사 범위를 정리했습니다.

```sh
pnpm install --frozen-lockfile
pnpm --filter @vnmaker/app dev --host 127.0.0.1 --port 5184 --strictPort
```

- [편집기](http://127.0.0.1:5184/studio.html)
- [플레이어](http://127.0.0.1:5184/)

일반 `pnpm dev`의 기본 포트는 5173입니다. 이번 검증은 다른 로컬 앱과의 충돌을 피하기 위해 5184를 사용합니다.

## 편집

같은 사이트에서는 한 탭만 편집 권한을 가집니다. 두 번째 편집기 탭은 저장하지 않고 대기하며, 기존 편집 탭을 닫으면 최신 저장본을 자동으로 엽니다. 서로 다른 작품도 활성 작품 저장소를 공유하므로 같은 제한을 적용합니다. 탭 잠금을 지원하지 않는 환경에서는 원고를 덮어쓰지 않도록 편집기를 열지 않습니다.

저장 표시는 현재 원고의 빠른 복구 저장과 작품 보관함 저장을 함께 확인합니다. 보관함 저장이 끝나기 전에는 **저장 중…**, 어느 한쪽이 실패하면 **저장 확인 필요**를 표시합니다. 오류 안내의 **다시 저장** 또는 Ctrl/Cmd+S로 최신 원고를 재시도할 수 있습니다. 실패가 계속되면 현재 탭을 닫기 전에 JSON으로 백업하세요. 브라우저에 저장됐다는 표시는 외부 백업이 있다는 의미는 아닙니다.

빠른 복구 원고를 읽지 못하면 자동 저장을 멈추고 **작품 보관함에서 복구**를 표시합니다. 현재 작품 ID의 보관함 원고를 검증한 뒤 제목과 저장 시점을 보여 줍니다. **손상 데이터 원문 받기**로 원문을 백업하거나 **이 보관함 원고로 복구**를 선택하세요. 복구 전에 손상 원문을 별도 브라우저 키에 보존하며, 보존에 실패하면 복구를 중단합니다. 보관함 저장 시점 이후의 편집이나 손상된 미디어까지 복원하는 기능은 아닙니다.

브라우저 종료로 빠른 복구 키 자체가 없어져도 보관함을 먼저 확인합니다. 활성 작품 정보까지 사라졌으면 최근 저장 작품을 제시하므로 제목과 저장 시점을 확인하세요. 보관함 쓰기는 엄격한 디스크 반영을 요청합니다. Windows Chromium의 렌더러·브라우저 프로세스 크래시 후 복구를 검사했지만, 전원 차단이나 모든 브라우저의 데이터 보존을 보장하지는 않습니다.

프로젝트 홈에서 분량과 연결 상태를 확인하고, 장면 편집에서 원고·화자·표정·배경·음악·선택지를 수정합니다. 대사마다 배우의 입장·퇴장과 작업 자세, 카메라, 배경·CG 전환, 음악 정지까지 지정할 수 있습니다. **미리보기 선택 경로**를 바꾸면 앞선 선택에 따른 대사와 연출을 검토할 수 있습니다. **집중 모드**는 미리보기를 넓히고, **Ctrl+K**는 전체 원고를 검색해 해당 줄을 엽니다.

속성 패널의 **작품 상태 변수**에서 켜짐/꺼짐·숫자·문자 초기값을 만들고, 각 선택지의 **선택 결과**에서 값을 변경합니다. **대사 표시 조건 / 선택지 표시 조건**은 여러 조건을 모두 만족할 때 표시하며, 숫자 크기와 값의 같음·다름을 비교할 수 있습니다. 예를 들어 `trust`를 0으로 시작해 한 선택에서 3으로 바꾸고, 다른 선택지에 `trust ≥ 3`을 지정할 수 있습니다. 도달 가능한 경로에서 선택지가 모두 닫히면 원고 검사에 오류가 표시됩니다. 지원하지 않는 기존 문자열 `cond`는 무시하지 않고 가져오기 오류로 알리며, 구조화된 `when` 조건을 사용해야 합니다.

숫자 변수의 **선택 결과 → 현재 값에 더하기 / 빼기**로 호감도·신뢰도를 누적할 수 있습니다. `3`은 현재 값에 3을 더하고 `-2`는 2를 뺍니다. 예를 들어 초기 신뢰도 2에서 두 선택의 +3, -2를 거치면 최종 값은 3입니다. 같은 변수에 고정값 설정과 증감을 동시에 지정할 수 없으며, 현재 값이 숫자가 아니거나 결과가 숫자 범위를 넘으면 원고 검사에 오류가 표시됩니다. 이 증감은 웹 게임과 Ren’Py 출력에 포함됩니다.

네이티브 **실행 게임 → 배포 ID와 업데이트**에서 고정 배포 ID를 확인할 수 있습니다. 첫 빌드 때 ID를 원고의 `nativeSaveId`에 저장하며, 같은 작품을 수정해 빌드해도 실행 파일 이름과 저장 폴더를 유지합니다. 작품 복제는 새 배포로 취급하여 이 ID를 제거합니다. 기존 출시작은 `options.rpy`의 `config.save_directory` 값에서 `vnmaker-` 뒤 ID를 입력해 연결하세요. ID 없는 원고를 CLI에서 직접 변환하면 기존의 원고 해시 방식이 유지됩니다. **저장 폴더 유지가 수정된 게임의 세이브 호환성을 보장하지는 않습니다.** 출시 업데이트마다 기존 세이브를 실제로 복원해 검증해야 합니다. 웹 게임의 원고 버전별 저장 정책은 변경되지 않았습니다.

에디터의 **업데이트 기준 빌드**에서 특정 출시본을 고정하거나 자동 선택을 사용할 수 있습니다. 기본값은 같은 배포 ID의 최근 완료 빌드입니다. 고정한 기준은 해당 브라우저·사이트의 작품별 설정으로 유지되며, 50개보다 오래된 기록은 **이전 빌드 더 보기**로 조회합니다. 선택한 ZIP의 크기·SHA-256과 원고 ID를 검증한 뒤, 그 안의 `script.rpyc`를 Ren’Py의 `old-game` 기준으로 사용합니다. 빌드 결과에 **이전 빌드 기준** ID가 표시됩니다. `output/editor-native-builds`의 해당 기록과 ZIP을 함께 보관하세요. 일반 게임 ZIP 가져오기는 컴파일 코드를 실행하지 않으며, 이 기준은 로컬에서 완료된 빌드 기록에서만 읽습니다. CLI에서는 `export-renpy.ts <game.zip> <sdk> <new-directory> --previous-build <completed-job-directory>`로 기준을 명시할 수 있습니다. 기준이 없으면 새로 컴파일하므로 기존 저장 위치가 보존된다고 가정하지 마세요.

원고의 장면 배열 순서는 네이티브 코드 배치에 영향을 주지 않으며, 추가한 상태 변수는 기존 세이브에 키가 없을 때만 초기값을 채웁니다. 획득한 값과 오래된 키는 유지합니다. 대사 수정·장면 배열 순서 변경·새 변수 추가를 포함한 두 버전 사이의 실제 저장 복원을 검증했지만, 장면/선택지 삭제·ID 변경·변수 이름/타입 변경의 자동 이행은 지원하지 않습니다. 다른 컴퓨터에서의 빌드 기준 복원, 모든 과거 버전의 세이브 호환성 검증은 추가 작업입니다.

**기준 출시본과 변경 비교**는 빌드 전에 기준 원고와 현재 편집본을 비교합니다. 장면 삭제, 대사 수·순서, 선택지와 분기 결과, 변수 타입·초기값, 배우 등록 순서와 연출 변경을 **중요 검토 / 검토 / 참고**로 표시합니다. 원고나 기준 선택을 바꾸면 이전 비교 결과를 지웁니다. **정적 비교이며 실제 세이브 호환성 검증이 아닙니다.** 동일 파일 경로의 바이트 변경, SDK·플랫폼 차이와 모든 과거 출시본을 검사하지 않습니다. 전체 건수는 계산하되 세부 기록은 중요도가 높은 순으로 최대 400개를 보관합니다.

기준 빌드가 있는 네이티브 출력에는 실제 내보낸 원고를 비교한 `release-compatibility.json`이 포함됩니다. 완료 화면에서 건수와 **이 빌드의 변경 검사 보기**를 확인하고 JSON을 내려받을 수 있습니다. 기록에는 기준 빌드·ZIP 해시와 두 원고의 해시가 포함되며, 다운로드 시 빌드 당시 기록 해시를 검증합니다. 사전 비교와 최종 출력은 원고 수정·에셋 경로 변환·자동 기준 선택 시점에 따라 달라질 수 있습니다. 중요한 변경이 있어도 빌드는 자동으로 차단하지 않으므로 출시 전에 해당 저장 위치를 실제로 복원해 검증하세요.

**내 음원 보관함**에서 MP3·Ogg(Vorbis/Opus)·16비트 PCM WAV를 음악·효과음·보이스로 가져옵니다. 장면 배경음악과 대사별 음악 전환·효과음·보이스에 지정할 수 있으며, 원본 파일은 게임 ZIP과 Ren’Py 프로젝트에 포함됩니다. 보이스는 다음 대사로 넘기면 멈추고, 자동 진행은 보이스가 끝나기를 기다립니다. 음량은 플레이어 설정에서 별도로 조절합니다. 파일당 50MB·30분, 한 번에 50개·합계 200MB, 보관함 5,000개가 현재 제한입니다. 브라우저의 ZIP 복원은 전체 512MB·12,000개 파일까지입니다.

**내 작품 → 폴더에 백업 / 폴더에서 가져오기**는 압축 없이 원본 파일을 하나씩 처리하여 ZIP의 전체 512MB 제한을 피합니다. 폴더 선택을 지원하는 Chrome·Edge에서 사용하며, 선택한 위치에 매번 새로운 백업 폴더를 만듭니다. 가져올 때는 `vnmaker-project.json`이 들어 있는 백업 폴더를 선택하세요. 완료 파일은 모든 원본 저장이 끝난 뒤 기록하며, 복원할 때 전체 파일 목록·크기·SHA-256을 검사합니다. 최대 12,000개 파일, 원고·목록 8MB, 기존 이미지·음원별 제한은 유지합니다. 폴더 백업은 실행 게임이 아니며, 가져온 작품은 브라우저 저장 공간에 복사됩니다. 디스크에서 직접 편집하는 모드와 실패한 가져오기의 미사용 에셋 정리는 아직 개발 과제입니다.

**원고·분량**은 선택 플래그에 맞는 대사만 포함해 시작부터 각 엔딩까지 계산합니다. 240/320/400자 읽기 속도를 비교할 수 있습니다. **스토리 맵**에서는 연결을 확인하고, **아트 디렉션**에서는 작품의 배경·CG·표정·작업 자세를 찾아 배치합니다. 장면 복제·이동·삭제는 연결을 확인하면서 사용하며 실행 취소로 되돌릴 수 있습니다.

**원화 감상**은 대사창을 숨겨 그림 전체를 보여 줍니다. 플레이어에서는 자동 진행도 멈추며, 감상을 끝내면 같은 대사로 돌아옵니다. 장면 삭제 시 바로 앞 장면을 연결 대상으로 고르면 삭제된 장면의 다음 연결·선택지·엔딩을 이어받습니다. 선택지의 의미를 유지할 수 없거나 직접 자기 자신으로 돌아오는 대상은 삭제 전에 차단합니다.

편집 내용과 선택한 장면·대사·작업 공간·집중 모드는 브라우저에 보관합니다. JSON 내보내기/가져오기를 지원하며, 실행 취소/다시 실행은 현재 세션의 최근 60회 변경을 보관합니다. **버전 기록**에는 이름을 붙인 최근 20개 원고 버전을 저장할 수 있고, 이전 버전을 복구할 때 교체되는 원고도 보관합니다. **여기서 플레이**는 선택한 대사와 미리보기 선택 경로로 시작하며 일반 플레이 저장과 분리됩니다.

파일 가져오기가 늦게 끝나도 그 뒤의 편집이나 더 최근에 가져온 파일을 덮어쓰지 않습니다. 버전 복원은 현재 원고의 백업을 마칠 때까지 대화상자 닫기와 배경 편집을 잠그고, 가져오기·복원 이후에는 이전 원고의 미리보기 선택을 초기화합니다.

플레이어는 **수동 저장 슬롯 6개와 자동 저장**을 제공합니다. 원고, 읽던 위치, 선택 플래그, 선택지 대기 상태와 읽은 기록을 함께 저장합니다. **이어서 읽기**는 가장 최근 저장을 사용하며, **저장 기록/불러오기**에서는 수동 슬롯이나 자동 저장을 직접 고릅니다. 브라우저 저장은 같은 기기·브라우저 안의 기능이므로 장기 백업이나 다른 기기로 옮길 때는 JSON 또는 게임 ZIP을 내려받으세요.

판본 표시 키가 없거나 오래됐어도 원고·버전 기록·플레이 저장을 일괄 삭제하지 않습니다. 이전 샘플을 정리했던 개발 단계의 삭제 동작은 일반 사용자 초기화에서 제거했습니다. 현재 판본으로 표시된 수정하지 않은 이전 기본 원고의 제한된 갱신만 유지합니다. 플레이어 첫 실행도 편집 원고 키에 샘플을 쓰지 않으므로 보관함 복구를 가리지 않습니다. 브라우저 저장은 저장소의 원본 JSON 파일을 직접 덮어쓰지 않습니다.

## 게임 ZIP으로 배포

**내 음원 보관함 → 작품 음악 페이드 (초)**에서 음악 시작·교체·정지 시간을 0~10초로 지정할 수 있습니다. 기본값은 1.2초이며 0초는 즉시 전환입니다. 원고와 게임 ZIP에 저장되고 Ren’Py 출력에도 같은 시간이 전달됩니다. 두 엔진의 실제 크로스페이드 곡선까지 같다는 의미는 아닙니다.

헤더의 **게임 ZIP**은 누른 순간의 편집 원고를 독립 플레이어·원화·음악·효과음과 함께 묶습니다. JSON만 내보내는 것과 달리 재생에 필요한 실제 파일을 포함합니다. 누락되거나 형식이 잘못된 에셋이 있으면 표시하고, 실패한 부분 ZIP을 완성본으로 다운로드하지 않습니다.

ZIP을 모두 푼 폴더를 정적 HTTP 서버의 **사이트 루트**로 제공하세요. 예를 들어 Python이 설치되어 있다면 압축을 푼 폴더에서 다음 명령을 실행할 수 있습니다.

```sh
python -m http.server 8080
```

그다음 [http://127.0.0.1:8080/](http://127.0.0.1:8080/)를 엽니다. **`file://` 더블클릭 실행과 사이트 하위 경로 배포는 지원하지 않습니다.** ZIP 플레이어에는 별도 게이트웨이·로그인·AI API가 필요하지 않으며, 원고별 저장 공간을 사용합니다. ZIP을 만든 뒤 편집한 내용은 새 ZIP을 내보내야 반영됩니다.

독립 HTTP 서버에서 실제 ZIP을 풀고 장편 경로를 끝까지 재생한 결과는 [배포 ZIP 검증](docs/qa/studio-completion-2026-09-06/export-bundle.md)에 기록했습니다.

이전 검증 시점의 로컬 산출물(이후 기능 변경은 포함하지 않음): [플레이 가능한 게임 ZIP](output/rain-blank-game.zip) — 81,167,840바이트, [편집용 원고 JSON](output/rain-blank.vn.json) — 227,482바이트. ZIP의 SHA-256은 `ace19570691a41bd01f4d132827305c41b786f91ee30c52e85c89ade1b3adee7`입니다.

## 네이티브 빌드 설정

Windows에 Ren’Py 8.5.3 SDK를 압축 해제한 뒤, `packages/app/.env.example`을 `.env.local`로 복사하고 `VNMAKER_RENPY_SDK`를 SDK 폴더 경로로 설정하세요. 상대 경로는 `packages/app`을 기준으로 해석합니다. 로컬 편집기를 다시 시작하면 상단 **실행 게임**에서 현재 편집본의 원본 파일을 준비하고, SDK 변환 → 오류 검사 → PC ZIP 빌드를 실행합니다. 설치 경로는 로컬 서버 설정에서만 받습니다.

창을 닫거나 페이지를 새로고침해도 같은 서버가 실행 중이면 작업 상태를 다시 확인할 수 있습니다. 완료 화면에서 ZIP과 전체 로그를 내려받고 SHA-256을 확인하세요. 원고·로그·빌드 결과는 `output/editor-native-builds/<작업 ID>/`에 보관합니다. 서버 재시작 후에도 **최근 빌드 기록**에서 완료·실패 기록을 다시 열 수 있습니다. 새 서버가 추적하지 않는 이전 진행 작업은 **실행 상태 미확인**으로 표시하며 자동 재실행하지 않습니다. 최근 50개 기록을 표시하고, 다운로드할 때 파일 크기와 해시를 다시 검사합니다. 한 서버에서 한 번에 한 작업만 실행하며, 단계별 제한 시간은 15분입니다. 현재 입력 게임 묶음은 512MB 이하이며 폴더 백업의 대용량 경로와는 별도입니다.

이 빌드 서비스는 같은 컴퓨터의 localhost 편집기에서만 접근할 수 있습니다. 정적 웹 호스팅에는 SDK 실행 기능이 포함되지 않습니다. Ren’Py `lint --error-code`가 실패하면 배포를 중단합니다. 완료된 PC ZIP은 엔진과 실행 파일을 포함하지만 macOS/Linux 실행, 코드 서명, 업데이트 간 저장 호환성, Steam 업로드는 별도 검증·설정이 필요합니다.

원본 전송을 마치고 변환·검사·배포 중인 작업은 **빌드 취소**로 중단할 수 있습니다. **종료 확인 중**을 거쳐 실제 빌드 프로세스 종료가 확인되면 **빌드 취소됨**으로 표시합니다. 취소된 작업의 부분 ZIP은 다운로드로 제공하지 않으며 로그와 작업 폴더는 남습니다. 실행 상태 미확인 작업이나 다른 서버의 프로세스에는 종료 명령을 보내지 않습니다.

## 구성

- `packages/app`: React 편집기, 플레이어, 순수 리듀서 기반 엔진
- `packages/content`: 원고 스키마, 파서, 장면·연결 검사
- `packages/ir`: 노드 기반 이야기 IR 및 컴파일러
- `packages/gateway`: 기존 로컬 모델 연동 모듈. 현재 플레이·편집 화면은 호출하지 않습니다.
- `tools/assemble-rain-novel.mjs`: 두 원고를 텍스트 앵커 기반 연출과 조립하고, 조건을 적용한 8경로의 최소 90분 분량을 검사

배우 원화는 녹색 배경의 생성 원본을 보관하며, 앱은 공유 WebGL 합성기로 표시할 때 배경을 제거합니다. 각 썸네일마다 별도 WebGL 컨텍스트를 만들지 않습니다. 이미지 파일 자체에 수동 비트맵 후처리를 적용하지 않았습니다.
