# 〈비가 남긴 빈칸〉 완성도 개선 QA

검토일: 2026-09-06. 이 문서는 현재 장편 원고와 편집기·플레이어의 기능, 검증 증거를 정리한다. 2026-09-05 보고서의 809행·26원화는 이전 판본의 수치이며 현재 기준은 아래와 같다.

**현재 상태: 완료.** 추가 적대적 감사 수정 후 타입 검사·프로덕션 빌드, 단위·도구 검사168개, 오디오15/15, 기존 회귀30/30, 기능 회귀10/10, 원화 QA4/4가 통과했다. 최종 원화 화면 PNG48장을 기록했다. 전달용 ZIP도 정식 빌드에서 내보내 별도 HTTP 서버의 17장면 경로 완주·슬롯 두 개의 저장과 복원·원화 감상 검증1/1을 통과했다. 아래 증거는 각 실행의 범위를 구별해 기록한다.

플레이 시간은 현재 선택 플래그로 읽히는 `Line.text`만 합산하고 공백을 제외해 320으로 나눈 **분량 추정**이다. 숨겨진 반대 분기, 제목, 선택지 문구, 아트 지시는 포함하지 않는다. 사람의 실제 독서 시간을 실측해 90분이라고 고정한 값은 아니다.

원고는 직접 집필·개정했고, 원화는 내장 이미지 생성 도구로 제작했다. **앱 내부 AI API는 사용하지 않았다.** 플레이·수동 편집·원고 계산·저장·독립 ZIP 실행에 모델 호출이나 계정 연결이 필요하지 않다.

## 이번에 달라진 점

### 원고와 선택

`s08`, `s12a`, `s13`에서 동의 철회와 책임을 재확인하던 문답을 실제 행동과 의견 충돌로 바꿨다. 꺼져 가는 녹음기, 손기록·책갈피 대조, 미래에게 몰리는 미완료 업무, 삭제 증거를 남기고 싶은 도현, 카드 잠금·압축 사본 정리를 다룬다. 장면의 결론을 반복하는 대신 그 결론 때문에 인물이 다르게 일하도록 했다.

첫 선택은 서린과의 포장 경험 또는 도현과의 장비·크레딧 경험으로 남는다. 두 번째 선택은 미래와 기록을 맞춘 약속 또는 서린과 우산 아래에서 나눈 대화로 남는다. `Choice.set`과 `Line.when`으로 합류 뒤 대사·배우·카메라를 구별하며, 조건에 맞지 않는 행은 본문과 모든 연출 큐를 함께 건너뛴다. 마지막 공개 여부는 실제 관람객을 맞는 엔딩과 물건·기록을 돌려주는 엔딩으로 이어진다.

### 연출과 편집

전용 CG 6장과 작업 자세 3장을 더했다. 새 CG는 빈 여섯째 고정대, 포장지의 귀퉁이, 녹음기와 살구색 끈, 서로 다른 기록, 공동 유리 조립, 첫 관람객을 각각 그린다. 원고의 소품·손동작을 이미지 담당과 맞춘 뒤 해당 문장에서 진입하고 복귀하도록 연결했다.

대사별 배우 입장·퇴장, 작업 자세와 기본 표정 복귀, 카메라, 배경·CG, 음악 전환·정지를 편집한다. 선택한 경로를 미리보기에서 바꿀 수 있다. 장면 복제·이동·삭제, 검색, 스토리 맵, 집중 모드를 사용하고 선택한 장면·대사·작업 공간·집중 모드를 새로고침 뒤에도 유지한다.

**원화 감상**은 대사창을 숨겨 CG의 손동작과 소품까지 보여 준다. 플레이어에서는 자동 진행을 멈추고, 감상을 끝내도 원래 대사 위치를 유지한다. CG 확대 때문에 가장자리가 잘리던 문제, 작업 자세의 소품이 자막에 가리던 문제, 390px에서 헤더 조작이 잘리던 문제를 수정하고 실제 픽셀·버튼 경계로 다시 확인했다. [48장 화면과 수정 상세](art-visual-qa.md)에 최종 결과를 기록했다.

삭제 후 연결 대상으로 바로 앞 장면을 고르면 삭제된 장면의 다음 연결·선택지·엔딩을 이어받는다. 분기의 의미를 유지할 수 없거나 직접 자기 자신으로 돌아오는 대상은 삭제 전에 차단한다. 삭제 때문에 유효한 엔딩이나 선택 플래그가 사라지는 경우를 단위 검사로 확인했다.

연출은 숫자 index만으로 조립하지 않는다. `tools/assemble-rain-novel.mjs`가 본문의 유일한 앵커를 찾아 적용하며 앵커가 사라지거나 중복되면 실패한다. 원고 수정으로 후일담이나 CG의 연결 지점이 잘못 이동하는 일을 방지한다.

### 저장과 복구

- 플레이어: **수동 슬롯 6개 + 자동 저장**. 원고·읽던 위치·선택 플래그·선택지 대기 상태·읽은 기록을 함께 보관한다.
- 이어서 읽기: 가장 최근의 저장을 선택한다. 저장 기록에서는 수동 슬롯과 자동 저장을 직접 고른다.
- 편집 미리보기: 일반 플레이 저장과 별도로 보관한다.
- 원고 버전: 이름을 붙인 **최근 20개 버전**을 브라우저 IndexedDB에 보관한다. 복구 전 교체될 원고도 버전으로 남긴다.
- 편집 실행 취소·다시 실행: 현재 세션의 최근 60회 변경을 보관한다.
- 저장 실패: 성공으로 표시하지 않고 경고한다. JSON 내보내기는 현재 편집 내용을 백업하는 별도 수단이다.

브라우저 저장과 원고 버전은 같은 기기·브라우저의 저장 기능이다. 저장소의 원본 JSON 파일을 덮어쓰거나 다른 기기로 자동 동기화하지 않는다.

비동기 가져오기는 요청 순서와 편집 시점을 확인한다. 이전 파일 읽기가 늦게 완료되어도 더 최근에 가져온 원고나 이후 편집을 덮어쓰지 않으며, 오래된 성공 알림과 실행 취소 이력도 남기지 않는다. 버전 복원은 현재 원고 백업이 완료될 때까지 닫기·Esc와 배경의 Ctrl+Z를 막고, 완료 후 미리보기 선택 플래그를 초기화한다. 테스트에서 실제 IndexedDB 쓰기 트랜잭션을 지연시켜 대기 중 잠금과 백업 완료 이후 복원을 확인했다.

### 독립 게임 ZIP

**게임 ZIP**은 현재 편집 원고, 독립 플레이어 JS/CSS, 원화·음악·효과음, 실행 안내를 함께 담는다. 에셋의 누락·HTML fallback·파일 변조와 취소를 확인하며, 부분 ZIP을 성공한 결과로 내보내지 않는다. 원고 내용에 따른 저장 namespace로 다른 작품이나 편집 미리보기의 저장과 분리한다.

실제 다운로드 ZIP을 `Expand-Archive`로 풀어 별도 정적 HTTP 서버에서 열었다. fixture의 조건부 본문과 줄별 연출, 저장·새로고침을 검증했고, 최종 정식 빌드의 장편도 17장면 경로를 완주했다. 두 수동 슬롯을 다른 대사 위치에 저장한 뒤 각각 복원했고, 원화 감상 중 자동 진행이 멈추는 것도 확인했다. 최종 ZIP은 **54개 파일·81,167,840바이트**이며 누락 파일·외부/API 요청·브라우저 예외는0건이었다. 이후 원고를 편집하면 새 ZIP으로 내보내야 한다.

지원 범위는 **압축을 푼 폴더를 HTTP 서버의 사이트 루트로 제공하는 실행**이다. `file://` 더블클릭과 사이트 하위 경로 배포는 지원하지 않는다. 예를 들어 압축을 푼 폴더에서 `python -m http.server 8080`을 실행한 뒤 `http://127.0.0.1:8080/`를 연다. 독립 플레이어에는 게이트웨이·로그인·외부 폰트·AI API가 필요하지 않다.

스크린샷 테스트는 실제 이미지의 로드·자연 크기와 캐릭터 합성 캔버스 준비를 기다린다. 문자열과 스키마 검사는 픽셀의 품질이나 효과음의 청취 품질을 대신하지 않으므로, 정적 검사 결과만으로 모든 시각·청각 연출이 완벽하다고 표시하지 않는다.

## 재현

저장소 루트에서 개발 서버를 5184에 띄운다. 기본 5173은 다른 앱과 충돌할 수 있어 이번 검증에서 사용하지 않았다.

```powershell
pnpm --filter @vnmaker/app dev --host 127.0.0.1 --port 5184 --strictPort
```

다른 터미널에서 기존 회귀를 실행한다. 테스트는 별도의 브라우저 컨텍스트를 사용한다.

```powershell
$env:VNMAKER_APP_PORT='5184'
node node_modules/@playwright/test/cli.js test tests/e2e/rain-novel.spec.ts tests/e2e/modern-studio.spec.ts tests/e2e/studio.spec.ts tests/e2e/edge.spec.ts --output=test-results/regression-completion
```

원고 재조립은 `node tools/assemble-rain-novel.mjs`다. 원고·연출 데이터와 두 감사 JSON을 다시 만들며, 기준에 못 미치는 경로가 있으면 실패한다. 전체 프로젝트 검사는 `pnpm typecheck`, `pnpm test`, `pnpm build`로 실행한다.
