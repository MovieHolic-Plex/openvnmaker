# VN Maker Studio — 적대적 visual QA

2026-09-05, Windows / Chromium. 직접 브라우저를 조작하고 스크린샷을 확인했다.
자동 검사가 통과한 뒤에도 이미지 위치와 반응형 화면을 재검토했다.

## 판정

변경 전 스튜디오는 대사 편집 미리보기 수준이었다. 수정 원고가 새로고침으로 사라졌고,
이미지 생성 결과가 작품에 반영되지 않았으며, AI 원고·분기 작성은 스튜디오에 연결되어 있지 않았다.

변경 후에는 **AI 분기형 작품 생성 → 제안 검토 → 적용 → 수동 편집 → 저장 → 두 엔딩 플레이**를 확인했다.
다만 현재 인물/에셋 구조에 맞춘 제작 프로토타입이며, 범용 캐릭터 제작과 게임 배포까지 완성된 제품은 아니다.

## 실제 모델 검증

- 모델: 로컬 `/api/generate/config`가 반환한 `gemini-3.8-flash-high`.
- 기존에 연결된 계정으로 UI에서 실제 `/api/generate` 요청 1회 수행. 텍스트 결과를 직접 생성했으며 fixture 응답을 사용하지 않았다.
- 요청: 폭우로 정전된 캠퍼스에서 졸업 전시 작품을 옮기는 단편. 4개 씬, 각 4줄, 다른 엔딩 2개.
- 결과: **「물감 번진 밤의 윤곽」**, 4개 씬 / 16줄 / 분기 1곳 / 엔딩 2개.
- 원본: [실제 AI 생성 작품 JSON](live-ai-story.vn.json). 출력 문구와 인물 배치를 수동으로 다듬지 않은 결과다.
- 브라우저에서 적용, 내보내기, 다시 가져오기, 두 분기 이동과 두 엔딩 도달을 확인했다.
- 엔딩: `Ending 1. 빗속에 갠 고백`, `Ending 2. 번지지 않은 계절`.
- 이미지 생성 **새 실계정 호출은 이번 QA에서 수행하지 않았다.** 이미지 API 응답과 파일 응답을 fixture로 주입해 생성 → 적용 → 저장 → 플레이의 연결을 검증했다.
- 다른 자동 AI 테스트는 네트워크 응답을 fixture로 주입한다. 실계정 성공과 오류 처리 테스트를 혼동하지 않는다.

## 검증 실행

- `pnpm typecheck` 통과.
- `pnpm test` 통과: content 24, IR 11, app 24, gateway 54, 도구 24 = 테스트 137개. 오디오 15개 검사 별도 통과.
- `pnpm build` 통과.
- 전체 `pnpm e2e` 실행: 36개 중 34개 통과. 실패 2개는 기존 타이틀 문구의 구분자에 의존한 assertion과, 새 플레이어 초기화 전에 테스트 훅을 읽은 테스트 동기화 문제였다.
- 두 테스트를 수정하고, 저장/불러오기 개선까지 반영한 뒤 `studio.spec.ts` + `edge.spec.ts` **23개 통과**.
- 타이틀 문구, 기존 플레이 저장/불러오기, 실생성 작품의 두 엔딩을 추가로 **3개 재검증 통과**.
- 마지막 CSS 정리 후 해당 해상도·그래프 캡처를 다시 확인했다. 전체 장편 플레이스루를 마지막 CSS 수정 후 또 실행한 것은 아니다.
- 최종 코드 기준 e2e 등록 시나리오는 38개. 단일 최종 전체 실행 38/38이라고 주장하지 않는다.

## 남은 제품 한계

1. 캐릭터 ID는 기본 3명과 주인공으로 고정돼 있다. 이름과 설정은 바꿀 수 있지만 새 배우·스프라이트 업로드는 구현되지 않았다.
2. 작품 JSON을 내보낼 수 있으며, 실행 가능한 게임 패키지와 에셋 번들 내보내기는 구현되지 않았다. 생성 이미지 주소는 해당 로컬 게이트웨이에 의존한다.
3. 자동 저장은 브라우저 저장소다. 서버 파일에 자동으로 저장하는 프로젝트 관리·여러 작품 전환·협업 충돌 해결은 별도 작업이다. 실행 취소 이력은 새로고침을 넘기지 않는다.
4. AI 작품 초안이 자동으로 모든 아트를 새로 만들지는 않는다. 실제 초안 첫 장면은 ‘정전된 실기실’이지만 기존 밝은 실기실 배경을 선택했다. 작품 맥락에 맞는 아트 디렉션과 장면별 새 이미지 제작이 필요하다.
5. 서사·화자 판단의 품질까지 보장하지 않는다. 실제 초안은 일부 묘사문을 주인공 대사로 넣었다. 구조적으로 플레이 가능하다는 것과 문학적 완성도는 다른 검증 항목이다.
6. AI 연결은 비공식 Antigravity 어댑터이며 제공자 상태·계정 할당량에 의존한다. 클라이언트의 ‘대기 취소’는 이미 시작한 서버 생성까지 중단하지 않는다.
