# momus / metis 플랜 게이트 런북

`momus` 고정밀 플랜 리뷰를 부르려다 이런 답을 받았을 때 읽는다.

> 계획은 완성됐고 구조 검증도 통과했습니다. 다만 momus 고정밀 리뷰는 이 세션에서
> 실행하지 못 했습니다

## 먼저: 모델도 API 도 문제가 아니다

Sonnet 이라서, `ccapi` 를 안 붙여서 막힌 게 아니다. 게이트는 `omo-ai` 플러그인이
**세션 안에서 굴리는 상태 머신**이고 전부 로컬에서 판정된다. 네트워크도 모델도
개입하지 않는다. 규칙은 여기 박혀 있다.

```
~/.bun/install/global/node_modules/omo-ai/plugin/extensions/omo-task.js
```

```js
{
  metis: { requiresSkills: ["ulw-plan"], requiresPlanArtifact: true, forbidsSkills: ["ulw-execute"] },
  momus: { requiresSkills: ["ulw-plan"], requiresPlanArtifact: true, forbidsSkills: ["ulw-execute"] }
}
```

## 세 조건이 전부 참이어야 스폰된다

| # | 조건 | 내부 이름 | 어디에 사는가 |
|---|---|---|---|
| 1 | **사용자가** 이번 세션에서 `ulw-plan` 을 요청했다 | `hasUserRequested` | 세션 메모리 |
| 2 | `.omo/plans/*.md` 를 이번 세션에서 읽거나 썼다 | `hasPlanArtifact` | 세션 메모리 |
| 3 | `ulw-execute` 를 아직 호출하지 않았다 | `forbidsSkills` | 세션 메모리 |

셋 다 **세션 메모리(`Map`)** 에 있다. 그래서:

- 세션이 바뀌면 1번이 사라진다. 어제 만든 플랜은 오늘 세션의 게이트를 열지 못한다.
- 파일이 디스크에 있어도 2번은 자동으로 참이 되지 않는다. **이번 세션에서 열어야** 한다.
- 3번은 한 번 어기면 그 세션에서 되돌릴 수 없다. 새 세션을 열어야 한다.

밖에서는 이 셋 중 어느 것도 "통과"라고 단정할 수 없다. 진단 도구가 `통과` 대신
`확실히 막힘` / `세션상태(확인불가)` 두 상태만 쓰는 이유다.

## 1번이 가장 자주 걸린다

에이전트가 아니라 **사용자 발화**만 이 조건을 채운다. 인정되는 경로는 셋뿐이다.

1. `/skill:ulw-plan` 슬래시 명령
2. 발화에 `ulw-plan` 이 들어감 (`/\bulw[-_ ]?plan\b/i`, `ulw plan` `ulw_plan` 도 됨)
3. 자연어 패턴에 맞는 요청

한국어 자연어 패턴은 **동사**를 요구한다.

```
/계획(?:서)?(?:부터|을|를|\s)*\s*(?:먼저\s*)?(?:세워|세우|짜|작성해|수립해)/
/(?:먼저|우선)\s*계획(?:서)?(?:을|를)?\s*(?:세워|세우|짜|작성해|수립해)/
```

| 발화 | 결과 | 왜 |
|---|---|---|
| `계획을 먼저 세워줘` | 열림 | `계획을 … 세워` |
| `먼저 계획을 짜자` | 열림 | `계획을 … 짜` |
| `계획서부터 작성해줘` | 열림 | `계획서부터 … 작성해` |
| `계획은 완성됐고 구조 검증도 통과했습니다` | **안 열림** | `완성됐고` 는 동사 목록에 없다 |
| `계획 어떻게 됐어?` | **안 열림** | 동사가 없다 |

플랜이 이미 끝났다고 **보고**하는 문장은 게이트를 열지 않는다. 게이트는 "플랜을
만들어 달라는 요청"만 센다.

## 발화가 통하는지 미리 확인한다

```bash
pnpm doctor:momus                                  # 규칙과 세 조건 상태
node tools/momus-gate-doctor.mjs --text "계획을 먼저 세워줘"
node tools/momus-gate-doctor.mjs --json            # 기계용
```

규칙을 베껴 두지 않고 실제 번들에서 읽으므로, omo 가 올라가면 이 도구의 판정도
따라간다. 번들을 못 읽으면 그 항목만 `fallback` 이라고 밝힌다.

진단에 성공하면 종료 코드는 **0** 이다. 게이트가 막혀 있다는 것은 진단 결과이지
도구의 실패가 아니다. 인자가 틀렸을 때만 1 로 끝난다.

## 해제 절차

1. **새 세션을 연다.** 이 세션에서 `ulw-execute` 를 이미 호출했다면 필수다.
2. 사용자가 직접 아래 중 하나를 친다.
   - `/skill:ulw-plan`
   - 발화에 `ulw-plan` 을 넣는다
   - `계획을 먼저 세워줘` 처럼 동사가 든 자연어로 말한다
3. 그 세션 안에서 `.omo/plans/*.md` 를 만들거나 읽는다.
4. 이제 `momus` 스폰이 허용된다.

## 함정

**시스템이 끼워 넣은 텍스트는 세지 않는다.** 자연어 판정 전에 이 블록들이 지워진다.

```
<ultrawork-mode>…</ultrawork-mode>
<system-reminder>…</system-reminder>
<skill name="…">…</skill>
```

그래서 `<system-reminder>계획을 먼저 세워줘</system-reminder>` 는 게이트를 열지
않는다. 에이전트가 대신 요청해 줄 수도 없다 — `source` 가 `extension` 인 메시지는
핸들러가 통째로 무시한다.

**스킬 태그는 요청이자 호출로 등록된다.** `<skill name="X">` 가 발화에 있으면 `X` 가
요청 목록과 호출 목록 **양쪽**에 들어간다. 즉 `<skill name="ulw-execute">` 가 한 번
스치면 그 세션의 momus 는 잠긴다. 진단 도구는 이 경우 경고를 찍는다.

```
경고: 이 발화는 금지 스킬 ulw-execute 를 호출된 것으로 등록해 세션을 영구히 잠근다.
```

**momus 는 일회용이다.** `task_send` 로 브리핑하거나 반박할 수 없고, 스폰 프롬프트도
하네스가 표준 계약(`.omo/plans/*.md` 경로 하나)으로 갈아치운다. 다시 받으려면 플랜을
고친 뒤 **새 momus 를 스폰**한다.

**팀 멤버로는 못 쓴다.** `momus` 와 `metis` 는 읽기 전용이라 팀 메일함에 쓸 수 없어
`team_create` 멤버로 넣으면 하드 리젝된다. `task(subagent_type="momus")` 로만 부른다.
