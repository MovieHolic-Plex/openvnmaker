# Web save manuscript snapshots

Inspection confirmed that current web saves contain the entire manuscript as well as the scene/index, flags, phase and history. Loading such a save uses its manuscript snapshot. Inserting lines in a newer manuscript therefore does not silently reinterpret that save's line index against the newer manuscript. However, the newer manuscript's corrections are also not adopted. This is snapshot restoration, not update migration.

The save/load picker now marks records whose manuscript differs from the currently playing manuscript. The annotation occupies a separate full-width row so the ordinary two-line summary clamp cannot hide it. The help text explains the snapshot behavior and that actual image/audio files are not stored in the save. Legacy saves without manuscript data receive a separate annotation. Loading a different manuscript also displays a short notice during scene/choice playback. The comparison ignores object-key order and otherwise compares complete JSON content; metadata-only differences can also trigger it. It is not a release version ID or compatibility verdict.

The retained browser fixture saves at a choice, inserts a line and changes the choice caption in the current preview manuscript, reloads, and restores the old slot. It verifies the visible annotation, old choice text, original line index, two-entry history without the newly inserted line, and the old choice's flag and destination. Four history/restore browser tests passed in 9.6 seconds. The final 390x844 picker screenshot was inspected. Workspace unit tests, typecheck and build passed.

Evidence: `evidence/save-snapshot-verified.log`, `evidence/save-snapshot-verified/`, `evidence/save-snapshot-tests.log`, `evidence/save-snapshot-typecheck-final.log`, `evidence/save-snapshot-build-final.log`. The first run exposed an incorrect exact-text test assertion (choice decorations) and a clipped annotation; the final run includes those corrections.

Limits: this fixture uses studio playback, not an installed application update or newly replaced production ZIP. Snapshot restoration was existing behavior and has not been redesigned. Assets removed or replaced at the old paths can still break or change restored visuals/audio. Moving old progress to a newer manuscript requires explicit migration semantics and persistent line/choice identities; these remain unfinished. Native Ren'Py save compatibility is a separate mechanism and is not established by this test.
